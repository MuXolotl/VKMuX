# VK Музыка API — руководство

Руководство по внутреннему API VK Музыки — закрытому интерфейсу, через который работают официальные клиенты (Android-приложение VK и VK Музыка, веб-раздел «Музыка»). Оно описывает полный доступ к музыкальному каталогу VK: медиатека пользователя, витрина рекомендаций, плейлисты, подкасты, тексты песен и навигация по разделам.

Этот API **не является публичным**. В публичной версии VK API (`v=5.x`) музыкальные методы отсутствуют или возвращают пустые списки: доступ к аудио VK закрыл для сторонних клиентов. Работать с музыкой можно только через внутреннюю версию `8.154`, имитируя окружение мобильного приложения.

Материал собран из двух источников:
- эталонный слепок ответов сервера — 956 вызовов по всем разделам и подразделам каталога (август 2026), каждое утверждение о формате ответа проверено по нему;
- код Android-приложения VK Музыки (библиотеки `catalogkit` и `vkapi2`) — параметры вызовов и структуры, которые в слепке не встретились. Такие места помечены «по приложению».

Связанный документ: [`VK-RESPONSE.md`](./VK-RESPONSE.md) — полный справочник моделей и структур ответов (каждое поле каждой сущности). Здесь — как вызывать API и как по нему ходить.

> **Правовая рамка.** Документ описывает техническую сторону обмена и предназначен для клиентов, читающих данные своего собственного аккаунта. Внутренний API может меняться без предупреждения; обрабатывайте неизвестные поля и типы мягко (сохраняйте как есть, не падайте).

## 1. Быстрый старт

Понадобится:

1. **`access_token`** с правами на музыку. Получается в результате авторизации клиента VK Музыки (через VK ID). Токен привязан к типу клиента; токены публичных standalone-приложений для музыкальных методов не подходят.
2. **Версия API `8.154`** — передаётся в каждом запросе.
3. **Заголовки мобильного клиента** — см. §2.

Проверочный вызов (текущий пользователь и корневой каталог):

```bash
curl -X POST "https://api.vk.ru/method/users.get" \
  -H "User-Agent: VKAndroidApp/8.32-13000 (Android 13; SDK 33; arm64-v8a; Google Pixel 7; ru; 1080x2400)" \
  -H "X-VK-Android-Client: new" \
  --data-urlencode "access_token=<TOKEN>" \
  --data-urlencode "v=8.154" \
  --data-urlencode "device_id=<android_id:gcm_id>" \
  --data-urlencode "lang=ru"

curl -X POST "https://api.vk.ru/method/catalog.getAudio" \
  -H "User-Agent: VKAndroidApp/8.32-13000 (Android 13; SDK 33; arm64-v8a; Google Pixel 7; ru; 1080x2400)" \
  -H "X-VK-Android-Client: new" \
  --data-urlencode "access_token=<TOKEN>" \
  --data-urlencode "v=8.154" \
  --data-urlencode "device_id=<android_id:gcm_id>" \
  --data-urlencode "need_blocks=1"
```

Первый вызов вернёт массив с объектом пользователя, второй — корневой конверт каталога с шестью разделами. Если вместо этого пришло `error.error_code = 8` — не прошла версия или заголовки (§2). Если `5` — токен не подходит (§1.1).

### 1.1. Про токены и сессию

- Срок токена ограничен: ошибки `1114`/`1117` означают, что сессию надо продлевать (процесс продления зависит от способа авторизации клиента, к музыкальному API отношения не имеет).
- Сервисные вызовы параметров запуска (`apps.getAppLaunchParams`) и сервисных токенов (`auth.getCredentialsForService`) для части типов токенов возвращают `100 (not integer)` — это не мешает работе с музыкой, обрабатывайте как «служба недоступна».

## 2. Транспорт: протокол, заголовки, версия

### 2.1. Эндпоинт и кодирование

Все запросы — `POST https://api.vk.ru/method/<имя.метода>` с телом в формате `application/x-www-form-urlencoded`. GET не используется.

### 2.2. Системные параметры каждого запроса

| Параметр | Значение | Назначение |
|---|---|---|
| `access_token` | токен сессии | Авторизация |
| `v` | `8.154` | Версия API — внутренняя версия Android-приложения |
| `device_id` | `<android_id>:<gcm_id>` | Идентификатор устройства (GCM-формат) |
| `lang` | `ru` | Язык ответов |

### 2.3. HTTP-заголовки

Каждый запрос обязан воспроизводить окружение Android-приложения:

| Заголовок | Значение |
|---|---|
| `User-Agent` | `VKAndroidApp/<версия> (Android <версия>; SDK <уровень>; <abi>; <производитель> <модель>; ru; <ширина>x<высота>)` |
| `X-VK-Android-Client` | `new` |
| `Referer` | `https://id.vk.ru` |
| `Origin` | `https://id.vk.ru` |
| `Sec-Fetch-*`, `Accept` | стандартный набор браузерных/клиентских заголовков |

### 2.4. Почему `8.154`

Музыкальные методы включаются серверной логикой по версии внутреннего клиента. С публичной версией `5.x`:
- `catalog.*` отвечает ошибкой `8` (invalid version),
- `audio.search`, `audio.get` и прочие возвращают пустые списки.

Без полного набора заголовков §2.3 сервер не выдаёт контент даже с правильной версией.

### 2.5. Оболочка ответа

Успех — всегда объект `response`:
```json
{ "response": { ... } }
```
Ошибка — объект `error`:
```json
{
  "error": {
    "error_code": 104,
    "error_msg": "Not found"
  }
}
```

Тип содержимого `response` зависит от метода: объект, массив (`audio.getById`, `audio.getPopular`, `audio.getStreamMixAudios`, `users.get`) или число (`audio.getCount`, `stats.trackEvents`). Сводная таблица — в конце [`VK-RESPONSE.md`](./VK-RESPONSE.md).

## 3. Модель каталога

Понимание этого раздела обязательно: витрина VK Музыки живёт не в `audio.*`, а в `catalog.*`, и построена иначе, чем типичные REST-ресурсы.

### 3.1. Скелет и сущности

Ответ каталожного метода («конверт») состоит из двух частей:

1. **Скелет**: секция → упорядоченный массив `blocks`. Блок — отображаемый ряд (карусель, список, заголовок, разделитель, кнопки). Блок знает *как* рисоваться (`layout`) и *что* показывать (`data_type`), но содержит не сами сущности, а списки их идентификаторов: `audios_ids`, `playlists_ids`, `links_ids` и т.д.
2. **Пакеты сущностей**: корневые ключи конверта `audios`, `playlists`, `links`, `audio_books`, … — массивы полных объектов.

Клиент обязан «разрешить» скелет: для каждого блока взять его `*_ids` и подставить объекты из пакетов **в том же порядке**. Порядок идентификаторов — это порядок отрисовки VK, перемешивать его нельзя.

```json
{
  "audios": [ { "id": 456239065, "owner_id": 720198974, "title": "...", ... } ],
  "section": {
    "id": "PUldVA8FR0Rz...",
    "title": "Главная",
    "blocks": [
      {
        "id": "PUlQVA8GR0R3...",
        "data_type": "music_audios",
        "layout": { "name": "list", "owner_id": 720198974 },
        "audios_ids": [ "720198974_456239065", "720198974_456239066" ]
      }
    ]
  }
}
```

### 3.2. Четыре формы конверта

| Форма | Ключи верхнего уровня | Методы |
|---|---|---|
| Корневой каталог | `catalog { default_section, sections }` | `getAudio` без `url`, `getAudioSearch`, `getAudioArtist` |
| Детальная секция | `section` | `getSection`, `getAudio` с `url` |
| Одиночный блок | `block` | `getBlockItems` |
| Замены вкладок | `replacements { new_next_from, replacements[{ from_block_ids, to_blocks }] }` | `replaceBlocks` |

Плюс набор пакетов сущностей произвольного состава (пустой у корневого каталога).

### 3.3. Навигационный граф

Точка входа — `catalog.getAudio` без параметров: шесть разделов-указателей («Главная», «Моя музыка», «Радио», «Обзор», «Книги и шоу», «Детям»), блоков и пакетов в ответе нет. Дальше страницы открываются тремя способами:

1. **`catalog.getSection(section_id)`** — основной переход. Применим к id корневых разделов, id «показать всё» (§3.4), id из кнопок `open_section`, id из `default_section` (поиск, артист).
2. **`catalog.getAudio(url=...)`** — переход по прямой ссылке страницы. Понимает адреса разделов (`audios<UID>?section=X`, `audio?section=X`); в том числе ведёт на «скрытые» разделы вроде `in_progress`, кнопок на которые в витрине нет (их дают кнопки `open_url`).
3. **`catalog.replaceBlocks(replacement_ids)`** — переключение вкладок-подразделов внутри секции (§3.5).

Одну страницу можно открыть несколькими адресами-псевдонимами: `vk.com`↔`vk.ru`, `audios<UID>?section=X`↔`audio?section=X`, по `section_id` и по `url`. Не считайте их разными секциями.

### 3.4. «Показать всё» и собственные страницы блоков

У разворачиваемых блоков есть `meta.show_all_info = { "section_id", "title" }` — адрес страницы блока (например, карусель «Мои треки» на «Моей музыке» разворачивается в полный список на своей странице). Открывается через `getSection`. Собственная страница отдаёт тот же контент в списочных раскладках (`large_slider` → `list`).

Но `show_all_info.section_id` часто указывает на секцию, которой блок сам принадлежит: это значит «блок уже развёрнут», а не «есть куда перейти». Такие переходы нужно отбрасывать, иначе страница ссылается сама на себя. Подробности и счётчики — VK-RESPONSE.md §6.1.

### 3.5. Вкладки подразделов

Блок с раскладкой `subsection_tabs` содержит кнопку `podcasts_subsection_tabs` со списком `options[]`: `{ "replacement_id": "#<section_id>/#<subsection_id>", "text": "Подкасты", "selected": 1 }`. Вкладка с `selected: 1` активна, её контент уже на странице, запрос за ней не нужен. Остальные вкладки — вызов `catalog.replaceBlocks` с токеном вкладки: в ответе блоки `from_block_ids` заменяются на `to_blocks`, порядок страницы сохраняется. Курсор пагинации страницы обновляется из `new_next_from`.

### 3.6. Пагинация (два уровня, курсоры opaque)

- Страница секции: `section.next_from` → `getSection(section_id, start_from=<курсор>)`. Продолжайте, пока `next_from` не исчезнет.
- Ряд блока: `block.next_from` → `getBlockItems(block_id, start_from=<курсор>)` — следующая порция элементов блока.

Размеры порций определяет VK (по слепку: 12–100 идентификаторов в зависимости от блока).

### 3.7. Эфемерные идентификаторы и ошибка 104

`section.id`, `block.id`, `default_section`, replacement-токены — зашифрованные opaque-строки. Их нельзя синтезировать: получил → вернул серверу как есть. Идентификаторы блоков протухают через некоторое время: повторный `getBlockItems` по старому `block_id` отвечает `104 (Not found)` — это штатно (~1% вызовов в слепке). Рецепт: перевыгрузить родительскую страницу и взять свежий id.

### 3.8. Ленивое наполнение блоков

Не каждый блок приезжает с содержимым:
- **`audio_books` на страницах секций всегда без `audio_book_ids`** — карусель книг наполняется только через `getBlockItems` (все 195 таких блоков в слепке);
- баннерные и смешанные блоки могут присылать пустые `*_ids` с наличным `next_from` — разворачивайте блоком;
- блок `action` сущностей не содержит вовсе (это кнопки и жанровые подборки).

### 3.9. Пустые секции — норма

Персональные подборки без подписок («Артисты и кураторы», «Вы начали слушать») и медиатеки закрытых/удалённых пользователей (`Музыка <имя>`, `DELETED`) возвращают секцию без блоков и пакетов. Показывайте пустое состояние, а не ошибку разбора.

### 3.10. Неизвестное завтра

VK добавляет типы блоков, раскладки и поля без предупреждения (пример: `market_items` появился у страниц артистов и отсутствует в таксономии приложения). Парсер должен:
- сохранять неизвестные поля как есть (пригодятся при повторной сериализации/кэшировании);
- не падать на неизвестном `data_type` или `layout.name` — рисовать универсально (заголовок + список) и логировать.

## 4. Справочник методов

### 4.1. Навигация и витрина (`catalog.*`)

Все методы этой группы принимают `need_blocks=1` (форму использует приложение) и/или эквивалентный `extended=1` — расширенная выдача с пакетами сущностей. Ответы описаны в §3.

#### `catalog.getAudio`

Корневой каталог или страница раздела по прямой ссылке. Точка входа в витрину.

| Параметр | Тип | Обязателен | Описание |
|---|---|---|---|
| `need_blocks` | int | нет | `1` — блоки и пакеты сущностей |
| `url` | string | нет | Прямая ссылка на раздел. Без неё — 6 корневых разделов |
| `owner_id` | int | нет | Владелец каталога |

Без `url` — конверт `{ "catalog": { "default_section": "...", "sections": [...] } }` с секциями-указателями «Главная» (`general`), «Моя музыка» (`all`), «Радио» (`radiostations`), «Обзор» (`explore`), «Книги и шоу» (`podcasts`), «Детям» (`audio_kids`). С `url` — каталог с `default_section` и, для адресов конкретных блоков, секция с блоками и пакетами (§3.3, §3.9). В Android-слепке простой URL `...?section=general` повторяет каталог-указатель; содержимое «Главной» надёжно получается через `catalog.getSection(default_section)`.

VK Web вызывает тот же метод внутри `web.api.vk.ru/method/batch.call` (`v=5.285`, `client_id=6287487`) с параметрами `url=https://vk.ru/audios<UID>`, `need_blocks=1`, `owner_id=<UID>` — обратите внимание: URL без `?section=general`. Этот вариант сразу возвращает наполненную «Главную» и пакет из 32 generated-плейлистов. Блок `music_playlists/recomms_slider` ссылается только на восемь из них; остальные принадлежат блокам жанров и настроений.

#### `catalog.getSection`

Детальная загрузка секции с блоками — основной рабочий метод навигации.

| Параметр | Тип | Обязателен | Описание |
|---|---|---|---|
| `section_id` | string | да | Opaque-идентификатор секции |
| `need_blocks` | int | нет | `1` — дерево блоков |
| `extended` | int | нет | `1` — расширенная выдача |
| `start_from` | string | нет | Курсор страницы из `section.next_from` |

Ответ: конверт `section` + пакеты секции. Пагинация — §3.6, истечение токенов — §3.7.

**Ошибки:** `8` (не та версия), `104` (секция не найдена или токен протух — §3.7).

#### `catalog.getBlockItems`

Подгрузка элементов блока: разворот ленивых каруселей (§3.8) и докрутка рядов.

| Параметр | Тип | Обязателен | Описание |
|---|---|---|---|
| `block_id` | string | да | `block.id` |
| `extended` | int | нет | `1` — расширенная выдача |
| `start_from` | string | нет | Курсор из `block.next_from` |

Ответ: конверт `block` + пакеты элементов блока.

**Ошибки:** `104` на протухшем `block_id` — перевыгрузить страницу.

#### `catalog.replaceBlocks`

Переключение вкладок-подразделов секции (§3.5).

| Параметр | Тип | Обязателен | Описание |
|---|---|---|---|
| `replacement_ids` | string | да | Токены замены через запятую (по приложению; на практике один — вида `#<section_id>/#<subsection_id>`) из `actions[].options[].replacement_id` |

Ответ: `replacements { new_next_from, replacements[{ from_block_ids, to_blocks }] }` + пакеты новых блоков.

**По приложению:** старое имя метода — `catalog.replaceSections(replacement_id)` (единственное число); актуальное — `replaceBlocks`.

#### `catalog.getAudioSearch`

Подсказки поиска и поисковая витрина.

| Параметр | Тип | Обязателен | Описание |
|---|---|---|---|
| `query` | string | нет | Поисковая строка. **Именно `query`**, не `q` |
| `need_blocks` | int | нет | `1` — блоки |
| `show_suggests` | int | нет | Показ подсказок (по приложению) |
| `requested_section_id` | string | нет | Подраздел выдачи (по приложению) |
| `context` | string | нет | Токен контекста из подсказки |

Без запроса — секция `search_suggestions` (пакет `suggestions`, обычно 20). С запросом — заглушка `catalog.default_section`: сама выдача открывается через `getSection`, а страница каждой подсказки — через её `context`.

**Ловушка:** поисковая строка передаётся в `query`. На `q` метод отвечает не ошибкой, а секцией подсказок — как будто запроса не было; выдача при этом молча теряется.

#### `catalog.getAudioArtist`

Страница исполнителя.

| Параметр | Тип | Обязателен | Описание |
|---|---|---|---|
| `artist_id` | string | да | Идентификатор артиста (как в объекте `Artist`, строковый). Принимает и `domain` — последний сегмент ссылки `vk.ru/artist/<domain>`; плитки артистов в каталоге отдают только её, без `artist_id` |
| `need_blocks` | int | нет | `1` — блоки |

Ответ: заглушка `default_section`; страница артиста — через `getSection`. Составные части по слепку (первая всегда шапка `artist_header`, остальное плавает): «Популярное», «Последний релиз», «Релизы», «Участие в релизах», «Концерты», «Об артисте» (`biography_layout`), «Мерч» (`market_items`), «Встречается в плейлистах», «Официальные страницы», «Музыкальные видео», «Вам могут понравиться».

**Ошибки:** `104` — артист не найден (неверный `artist_id`).

#### `catalog.getAudioCurator`

Страница куратора подборок. Параметры: `curator_id` (обязателен), `url`, `need_blocks`. Ответ — заглушка `default_section` → `getSection`. Ссылки на страницы кураторов приходят плитками `links` в разделе «Обзор» → «Кураторы». *(Параметры — по приложению; в слепке страницы кураторов открывались через `getAudio(url)`.)*

#### Методы витрины, известные по приложению, но не проверенные слепком

| Метод | Параметры | Назначение |
|---|---|---|
| `catalog.getPodcasts` | `category_id`, `owner_id`, `need_blocks=1` | Подкасты по категории |
| `catalog.getAudioBooks` | `genre_id`, `need_blocks=1` | Витрина аудиокниг по жанру |
| `catalog.getAudioBooksPerson` | `person_id`, `genre_id`, `need_blocks=1` | Страница персоны книг (автор/читец) |
| `catalog.getPersonAudioBooks` | `person_id`, `need_blocks=1` | Книги персоны |
| `catalog.getAudioAuto` | `need_blocks=1` | Каталог для Android Auto |
| `catalog.getAudioBook` | — | **Ошибка `3`** — метода не существует, книги не открываются поодиночке |

### 4.2. Медиатека и поиск аудио (`audio.*`)

#### `audio.get`

Список аудиозаписей пользователя или сообщества.

| Параметр | Тип | Обязателен | Описание |
|---|---|---|---|
| `owner_id` | int | нет | `>0` пользователь, `<0` сообщество; по умолчанию — текущий профиль |
| `count` | int | нет | 1–200 (по умолчанию 20) |
| `offset` | int | нет | Смещение |
| `album_id` | int | нет | Альбом/плейлист |
| `extended` | int | нет | `1` — полные метаданные и профили |

Ответ: `{ "count": int, "items": [Audio], "groups": [...], "profiles": [...], "next_from": "..." }` (`next_from` — пока есть продолжение выборки).

#### `audio.getById`

Метаданные и свежие прямые ссылки на поток по списку треков.

| Параметр | Тип | Обязателен | Описание |
|---|---|---|---|
| `audios` | string | да | `owner_id_audio_id` через запятую; для чужих/приватных — `owner_id_audio_id_accesskey` |

Ответ: массив `[Audio]`.

Особенности:
- принимает только числовые идентификаторы — иначе `100 (not integer)`;
- треки с `url: ""` (ограничение `content_restricted`) при повторном запросе пачкой часто получают рабочую ссылку;
- пачка обрабатывается целиком: один битый id роняет весь вызов — дробите запрос;
- эпизоды подкастов и аудиокниги методом не обслуживаются.

**Ошибки:** `100` (формат), `104` (не найдено).

#### `audio.getCount`

Число аудиозаписей медиатеки. Параметр: `owner_id` (обязателен). Ответ: целое число.

#### `audio.getPlaylists`

Плейлисты и альбомы владельца: `owner_id` (обязателен), `count` (1–200), `offset`. Ответ: `{ "count": int, "items": [Playlist], "profiles": [...], "groups": [...] }`.

#### `audio.getPlaylistById`

Плейлист целиком через аудио-API: `owner_id`, `playlist_id` (обязательные), `access_key`, `audio_count`. Ответ: полный объект плейлиста с `genres`, `is_following`, `play_button` (модель — VK-RESPONSE.md).

#### `audio.getLyrics`

Текст песни: `audio_id` в формате `owner_id_audio_id` (обязателен). Ответ: `{ "credits": "...", "md5": "...", "lyrics": { "language": "ru", "text": [...], "timestamps": [...] } }`. Когда текста нет — ошибка `104` (пустое состояние, не сбой).

#### `audio.getPopular`

Чарт популярного: `count` (1–100, по умолчанию 20), `offset`, `only_eng` (`1` — только зарубежное). Ответ: массив `[Audio]`.

#### `audio.getRecommendations`

Персональные рекомендации или похожие треки: `count` (до 100), `target_audio` (`owner_id_audio_id` — источник похожести; без него — общая лента). Ответ: `{ "count": int, "items": [Audio] }`; треки также приходят полем `audios` — объединяйте оба.

#### `audio.search`

Поиск по аудиобазе: `q` (обязателен), `count` (1–300), `offset`, `sort` (`0` релевантность, `1` дата добавления, `2` длительность), `extended`, `search_own` (`1` — только свои). Ответ: `{ "count": int, "items": [Audio] }`. Рекомендуемый вход в витрину поиска — `catalog.getAudioSearch` (§4.1), классический метод нужен для плоской выдачи треков.

#### `audio.getStreamMixSettings` и `audio.getStreamMixAudios`

Персональный бесконечный поток («Микс»):

| Метод | Параметры | Ответ |
|---|---|---|
| `audio.getStreamMixSettings` | `mix_id` (`common`, `my_music` или id из пакета `audio_stream_mixes`) | `{ "settings": { "title": "...", "mix_categories": [...] } }`; для части миксов — пустой массив `[]`, принимайте обе формы |
| `audio.getStreamMixAudios` | `mix_id`, `append` (номер порции 0,1,2…), `count`, `options` (JSON `{ "category_id": ["option_id"] }` — выбранные настроения) | Массив `[Audio]` |

#### `audio.getRestrictionPopup`

Объяснение недоступности трека (регион, подписка): `audio_id` (`owner_id_id`). Ответ: `{ "title": "...", "icons": [{ "url", "width", "height" }] }` либо пустая структура.

#### `audio.getUploadServer`

Сервер загрузки собственного MP3. Без параметров. Ответ: `{ "upload_url": "https://pu.vk.ru/gu/audio/v2/upload?token=..." }`.

### 4.3. Подкасты (`podcasts.*`)

Эпизоды воспроизводимы: пакет `podcast_episodes` каталожных конвертов несёт каждому эпизоду `url` потока и `file_size` (проверено всеми эпизодами слепка). Методы по коду приложения:

| Метод | Параметры | Ответ |
|---|---|---|
| `podcasts.getEpisode` | `owner_id`, `episode_id` | Полный объект эпизода (`AudioTrack`) |
| `podcasts.getRandomEpisode` | — | Случайный эпизод |

### 4.4. Составные вызовы (`execute.*`)

#### `execute.getPlaylist`

Плейлист + первая порция треков одним запросом.

| Параметр | Тип | Обязателен | Описание |
|---|---|---|---|
| `owner_id` | int | да | Владелец |
| `id` | int | да | Идентификатор плейлиста |
| `access_key` | string | нет | Для чужих/приватных |
| `audio_count` | int | да | Сколько треков вернуть |
| `audio_offset` | int | нет | Смещение треков |
| `count` | int | нет | Размер выборки |
| `need_playlist` | int | нет | `1` — добавить объект плейлиста |
| `need_owner` | int | нет | `1` — добавить владельца |
| `func_v` | int | нет | Версия функции (`10`) |

Ответ: `{ "audios": [Audio] }`; при `need_playlist=1` — также `playlist`, `profiles`, `groups`. Для полной выгрузки читать нужно верхнеуровневый `audios`: в проверенном слепке `playlist.audios` содержит только preview из 3 треков, тогда как верхний массив содержит запрошенные 20. Пагинация: увеличивать `audio_offset` на размер полученной страницы, повторяя вызов до `playlist.count`/известного `count` плитки или пустой страницы.

Для generated-плейлиста передаются `owner_id` и отрицательный `id` ровно из плитки плюс её `access_key`. `audio.getPlaylistById(owner_id, playlist_id=<negative>, access_key)` полезен для полного объекта, но в проверенном слепке треков не вернул. Вызов может лениво пересобрать ежедневный плейлист: свежий прогон получил новые `count`, `subtitle_badge` и `update_time` для `-25…-29` сразу после открытия.

Если известный generated-ID отсутствует в текущем блоке, scanner умеет сделать явный пробный запрос через `--force-generated <id[:access_key]>`. Это диагностический fallback, а не доказательство стабильности ID: сначала следует пробовать без ключа, затем — с ранее снятым ключом того же аккаунта.

Прочие функции приложения: `execute.getPodcastEpisodesWithInfo` (`owner_id`, `count=100`, `offset=0`, `func_v=4`) — эпизоды подкаста с метаданными.

#### `users.get`

Публичная информация пользователей. `user_ids` (список или `screen_name` через запятую; пусто — текущий), `fields` (`photo_base,photo_100,photo_200,photo_400_orig,photo_max,screen_name,counters,country,city,status,verified`). Ответ: массив `[User]`. В `counters` — счётчики медиатеки (`audios`, `albums`, `clips_followers`, …): ими заполнены карточки «Музыки друзей» и кураторов.

## 5. Коды ошибок

| Код | Значение | Действие клиента |
|---|---|---|
| `3` | Unknown method | Метода в API 8.154 нет (`audio.getCatalog`, `audio.getBroadcastList`, `audio.addLike`/`removeLike`, `catalog.getAudioBook`) — не вызывать |
| `5` | Авторизация не удалась / невалидный токен | Обновить сессию или повторный вход |
| `6` | Too many requests per second | Пауза, повтор с экспоненциальной задержкой |
| `8` | Неверная версия API | Проверить `v=8.154` и заголовки (§2) |
| `9` | Flood control | Пауза перед следующей серией |
| `14` | Captcha needed | Показать пользователю капчу |
| `17` | Validation required (2FA) | Запросить подтверждение входа |
| `27` | Ключ доступа недействителен | Перечитать сущность ради свежего `access_key` |
| `29` | Rate limit | Остановиться до сброса лимита |
| `100` | Неверный параметр | Проверить имена/типы; для `apps.getAppLaunchParams`/`auth.getCredentialsForService` означает «служба закрыта для этого токена» |
| `104` | Not found | Пустое состояние (нет текста) или протухший токен секции/блока — §3.7 |
| `1114` | Токен истёк | Продлить токен |
| `1116` | Расхождение времени с сервером | Повторить запрос |
| `1117` | Токен устарел | Продлить токен |

## 6. Подводные камни (сводка)

- Внутренняя версия `8.154` + полные заголовки приложения — без них музыки нет (§2).
- Каталог читается «скелет + пакеты»: склейка по `*_ids` в порядке VK (§3.1).
- Идентификаторы секций/блоков/замен — opaque-строки, хранить и возвращать как есть; протухают — `104` и перевыгрузка (§3.7).
- Аудиокниги на секциях ленивые: всегда `getBlockItems` (§3.8); ни книги, ни их коды не играют через `audio.getById`.
- Пустые секции и пустой `[]` у `getStreamMixSettings` — валидные ответы, а не поломки (§3.9, §4.2).
- Эпизоды подкастов играются из каталога (пакет `podcast_episodes` с `url`); через `execute.getPlaylist(id=-100)` и `audio.getById` — нет (§4.3).
- В `audio.getRecommendations` треки бывают и в `items`, и в `audios` (§4.2).
- Страницы псевдонимов (`vk.com`↔`vk.ru`, `audios<UID>`↔`audio?section=`) — одна и та же секция (§3.3).
- Неизвестные типы/поля — сохранять и не падать (§3.10).
